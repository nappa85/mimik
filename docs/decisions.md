# Decisions in force

One line per decision, with its date and ID. Superseded decisions are removed; git history has the rest.
Bare plan IDs are namespaced by section: under "Catalogues", D1–D12, Q and R are the catalogue plan's; under "Formulas and sheet values", D1–D11 are the list-editing (M4) plan's, cited in code as "plan Dn", and F- and M3- prefixes mark the earlier formula plans.
Assisted-sheet IDs are D-B…D-AA and V, U, N, S, P. Project rules (schedule, review, containers, secrets) live in `AGENTS.md`.

## Product direction and rules review

- **PROD-1** (2026-10-11) Mimik is a standalone, open-source, sheet-first companion for players at a physical table; it is not a virtual tabletop.
- **PROD-2** (2026-10-19) Assisted paper sheet: help the player as much as possible and never force anything; improve paper and pencil rather than replace it.
- **PROD-3** (2026-10-18) Assist, don't police (DL-1, DL-2): violations warn and never block; every change is logged and revertible, with a suggested fix where possible. A Master may open a sheet, its warnings and history; no automatic GM alert feeds or dashboards.
- **PROD-4** (2026-10-18) Advancement is context-driven (DL-3): an out-of-context edit (such as max HP) warns; raising the level opens a guided context that highlights the fields to change, with hints, checked against the before state.
- **PROD-5** (2026-10-15, refined 2026-10-18) The core is game-agnostic (DL-4): games are runtime definitions (data) from owner-supplied sheets and manuals; Rust knows only structural blocks; no new per-game compiled logic. Native MÖRK BORG code is an evaluation fixture.
- **PROD-6** (2026-10-11, refined 2026-10-15) Extension uses declarative definitions and packs; executable plugins (WASM or subprocess) only for gaps the data contract demonstrably cannot cover; incomplete coverage is shown as incomplete.
- **PROD-7** (2026-10-15) A game package can enable several books, each with its own identity, edition, revision and section tree; cross-book references and precedence are explicit, never merged by title.
- **PROD-12** (2026-10-15, refined 2026-10-19) Derived values are declarative CEL formulas evaluated in Rust, never template JavaScript; no other scripting language or rules DSL is added.
- **PROD-15** (2026-10-13) Self-hosted on a private LAN, never publicly exposed; instance owners supply lawfully obtained manuals and are responsible for their use.
- **PROD-18** (2026-10-15, extended 2026-10-19) The Owner may register rulesets, publish and withdraw definitions and administer catalogues from the browser as well as the CLI, through the same shared transitions, with account-attributed audit and no campaign access; Masters and players have no registry rights.
- **PROD-22** (2026-10-12) Prototype records are disposable: wipe them rather than weaken new schemas, invariants or permissions; no implicit compatibility exception in new definitions.
- **PROD-23** (2026-10-30, user) Sheets look like the official paper sheet: the owner uploads the official template (PDF or PNG/JPEG, kept in the data folder like manuals, never shipped) and values are drawn in its write-in areas, because position gives fields context; no generic form. Desktop and tablet are the target; phones are second-class (zoom and pan, no reflowed layout). Long text never overflows silently (shrink to a minimum size, then a "more" marker opening the full text). Canonical data stays independent of layout. Plan: ROAD-2.
- **RR-1** (2026-10-19) Number fields accept anything the player types; the app warns and offers a solution instead of refusing.
- **RR-2** (2026-10-19) An item not in the catalogue is accepted with a warning and the catalogue match offered (reverses catalogue Q4); without a match the app cannot know the item's details.
- **RR-3** (2026-10-19) Saving is always allowed, but a sheet that a formula or ruleset shows to be invalid (a warrior with spells, max HP out of range) is flagged as not validated.
- **RR-4** (2026-10-19) Typeahead and suggestions accept anything the user writes, suggest a correction, then validate.
- **RR-5** (2026-10-19) JavaScript may make sheets interactive: list row actions, typeahead, catalogue picking and live recompute.
- **RR-7** (2026-10-19) Controls are chosen per field: derived values may later become overridable, and fields (booleans included) may need custom inputs.
- **RR-8** (2026-10-19) Capacity limits (campaigns, sheets, catalogue entries) are safety-only: generous technical bounds against runaway memory or disk use, far above any real group's needs; no product-level caps.
- **RR-10** (2026-10-19) History is not limited to naming what changed; it may show values.

## Assisted sheet entry

- **D-B / D-R** (2026-10-19) A picked catalogue name is stored as plain text; once the player answers "Which Sword?", the entry key is stored beside it in a declared optional text property, and the cell still shows the text.
- **D-C / D-S** (2026-10-19) Each field and list cell saves on its own on Enter; lists keep Add, Remove and Move, plus a quick-add line ("3 torches", "healing potion x2") with a deterministic parse in the POC.
- **D-AA** (2026-10-19) With JavaScript a field also saves when the player leaves it, only if its value changed since its last save or offer; without JavaScript Enter is the only way.
- **D-D** (2026-10-19) The model quality bar (EVAL-1) is waived for the POC and revisited before release; engineering gates stay.
- **D-E** (2026-10-19) The sheet's readers (custodian and Masters) see raw scribbles and change notes in history.
- **D-F / D-J** (2026-10-19) The model reads the phrase, the target, stored number and enum fields, list-row item names and their linked catalogue entry text; never notes, backstory or multiline text.
- **D-G** (2026-10-19) Only the assistant and live suggestions need JavaScript; typing, arithmetic, notes, Undo and every save work without it.
- **D-H** (2026-10-19) The provider client comes from an established Rust library (`genai` or `rig-core`); if none can send the structured-output schema or grammar, stop and ask. Candidates (Project-STROT via pyo3 or a Rust port included) are judged on results.
- **D-I / D-K** (2026-10-19) Multi-field bundles (applied and undone as one) and dismissible reminders are their own step after model interpretation; POC knowledge is item names plus linked entry text.
- **D-M** (2026-10-19) `null` is the unknown value of every integer cell: blank input is unknown, and an unreadable number in a new row, newly present property or on create is stored as unknown with its scribble.
- **D-N / D-X1** (2026-10-19) Undo covers the last change of each field only, including a blanked (`erased`) value; older history is viewable.
- **D-O** (2026-10-19) A name links to a catalogue entry automatically only when exactly one eligible entry matches; otherwise the sheet asks "Which Sword?".
- **D-P** (2026-10-19) Stale or expired model proposals never become a literal; they need reconfirmation.
- **D-Q / D-X4** (2026-10-19) Sign-led input ("-15") on a number field is applied literally, then a non-blocking, dismissible offer "Did you mean 84 − 15 = 69?" switches in one click; multi-term input ("84 -15") is computed directly.
- **V3** (2026-10-19) "-5+3" is a sign-led sum: applied as −2 and offered relative to the value before ("84 − 5 + 3 = 82"); the leading sign must touch its digits.
- **ASSIST-1** (2026-10-19) U+00A0 and U+202F count as spaces in number entry; other Unicode spaces and full-width digits stay unreadable.
- **D-T** (2026-10-19) Change notes are written in the save's transaction, insert-only, for integer, enum and boolean cells only; sealing and verification come before release (L1).
- **D-U / D-X2** (2026-10-19) A save that changes nothing writes no revision and no note. History has no cap in the POC; a per-account write-rate limit or storage guard is required before release.
- **D-V** (2026-10-19) Removing a list row happens at once, with Undo right after; no confirmation.
- **D-W** (2026-10-19) Any saved decrease of a top-level number field may trigger a reminder; the model judges relevance, with no owner marking.
- **D-X3** (2026-10-19) Sheet writes wait up to 2 s for the `JOBS` permit, then answer a styled 503 page that keeps the player's entry; reads do not wait.
- **U4** (2026-10-19) On a nullable integer field, "Known" with a blank value is unknown (`erased`), not refused.
- **U7** (2026-10-19) Number input a note cannot hold faithfully (over 200 characters, or control characters) is refused with 422 instead of becoming a scribble.
- **U8** (2026-10-19) An unknown shows as `placeholder="?"` on an empty control (never a literal "?" value), or as "? (unknown)" under a scribble.
- **N2** (2026-10-19) A cell whose current note is a scribble on its saved value echoes the scribble in its control, so re-posting is a no-op; accepting the kept value requires typing it.
- **N3** (2026-10-19) New cells (create, new rows) get notes only for interpreted sums and scribbles, not for plain literals.
- **N7** (2026-10-19) A note insert must name the sheet's live, active `create`/`edit` revision under the request auth of that revision's actor.
- **S1** (2026-10-19) Switch and Undo post exactly `csrf`, `base`, `note` and are bound to the note (still current, cell still holding its `after`), not to the page revision.
- **S3** (2026-10-19) "Hide" on the switch offer is CSS-only and stores nothing; the offer returns on reload while its note is current.
- **S5** (2026-10-19) Undo is offered only when the note's value before differs from its value after.
- **P1** (2026-10-19, revised 2026-10-20) A saved page saves each list cell, new row and row action on its own; the full-form route still accepts the full-form key set and a slice-1.5a list form (pages loaded before per-cell save), whose draft operations re-render in the full form.
- **P2** (2026-10-19) A unit or cell form's single Save comes after its control.
- **P4** (2026-10-19) The D-X3 wait covers unit and list-unit routes and full-form and list-form edits; switch, Undo and create keep the immediate 503. CSRF and session are checked before the wait.
- **P5** (2026-10-19) Unit save order: malformed or zero `base` 400, `base` above L 409, no-op "No change" 200, changed unit 409, refused value 422.
- **P9** (2026-10-19) A scribble is quoted under its cell to 32 characters; its control echoes it in full.
- **ASSIST-2** (2026-10-19, coordinator default; revised 2026-10-20) Row-unit host checks for cells and row actions, in order: malformed `base` 400, `base` above L 409, row not in the base snapshot 400, row in the base but removed since 409 (Remove: "No change", ASSIST-11), then value conflict and no-op; a forged edge move is 400; Add stops at 256 rows; Undo with before `{"absent":true}` makes the property absent.
- **ASSIST-3** (2026-10-19, coordinator default) Quick-add is refused at admission (no quick-add line) for lists with a required text or multiline property other than the mapped name; the mapped name and quantity are filled even when optional.
- **ASSIST-4** (2026-10-19, coordinator default; revised 2026-10-20) Validity flag (RR-3, slice 1.7): the header of the sheet and of each history revision page shows "Not validated" when any check is violated, not evaluated or in error, or rule coverage is unavailable; the history list shows none (ASSIST-19); saving is always allowed.
- **ASSIST-5** (2026-10-19, coordinator default) Reminder provenance extension: a reminder option may use a number only if it appears in the text of the catalogue entry it cites, bound by catalogue version and entry key, and the option shows its source ("from Shield: …"); everywhere else every number must appear in the phrase or equal the target's value, except the divisors a fraction word admits (ASSIST-38).
- **ASSIST-6** (2026-10-20) List routes name the list field, row and property by index (`cells/{f}/{r}/{p}`, `lists/{f}/rows`, `lists/{f}/rows/{r}/{action}`); the row index is read at `base` and mapped to its host ID there. Three 64-character IDs per cell form did not fit the page bound (D7).
- **ASSIST-7** (2026-10-20) A page's row-cell switch and Undo buttons submit the short note key `<revision>:<f>.<r>.<p>`, resolved at `base`; typed `field:`, `cell:` and `row:` keys stay accepted.
- **ASSIST-8** (2026-10-20) Move up, Move down and Remove are buttons of one page-level form (`form` and `formaction`), never inside a cell form, so Enter in a cell cannot trigger them; after a Move the moved row's Move button keeps focus (`?focus=`).
- **ASSIST-9** (2026-10-20) "Row removed · Undo" is offered for each list's latest row note only, and Undo accepts only that note.
- **ASSIST-10** (2026-10-20) A removal is a `literal` row note (`row present` → `row absent`) on `row:<list>/<host>`; its Undo writes `reverted` with `target` and re-inserts the row as a new row (new host ID, no cell Undo).
- **ASSIST-11** (2026-10-20) Remove of a row already gone is "No change" (a stale no-op, D-U), not 409.
- **ASSIST-12** (2026-10-20, coordinator decision) A cell save whose row was removed (since the page, or before the writer's transaction) is a 409 that shows the draft read-only under "its row was removed", never in the row now at that index; 400 stays for rows that never existed at `base`.
- **ASSIST-13** (2026-10-20) A list's quick-add mapping is `items.quick_add` (`name` a text property, never multiline; `quantity` an optional integer property), omitted when absent so old hashes are kept; a required enum or boolean also refuses it.
- **ASSIST-14** (2026-10-20, coordinator default) The quick-add name is stored as typed (trimmed, never recased); counts are ASCII digits; a trailing count needs white space, then `x` or `×` ("potion x2", "potion x 2"; "Box 2", "Hex 5" and "potionx2" stay names); without a mapped quantity the whole line is the name, so a typed count is never lost.
- **ASSIST-15** (2026-10-20, coordinator default) A blank quick-add line is 200 "Nothing to add" with no revision; over 200 characters or a control character is 422 with the entry kept; an entry refused by a full list is kept read-only to copy.
- **ASSIST-16** (2026-10-20) After a quick-add the page returns with the empty line focused (`?focus=quick-<f>`); the sheet view ignores a repeated `focus` and any other query parameter instead of refusing them.
- **ASSIST-17** (2026-10-20, coordinator default) Rule coverage (ASSIST-4) exists only for a supported runtime pin whose formula layer declares at least one check and accepted the saved values; native MÖRK BORG, unsupported and formula-free pins and definitions without checks always show "Not validated".
- **ASSIST-18** (2026-10-20, coordinator default) A derived value that could not be computed also flags the revision ("N derived values not computed"); unknown inputs and evaluation errors both count as "not evaluated", with the code in the checks section.
- **ASSIST-19** (2026-10-20, coordinator default) "Each history revision" is each revision page (`/history/<n>`), flagged from the one evaluation that page already does; the history list evaluates nothing (RR-L1).
- **ASSIST-20** (2026-10-20, coordinator default) The create page shows no flag (nothing is saved yet); a refused draft's re-render shows the saved revision's flag, never one of the draft.
- **ASSIST-21** (2026-10-20, coordinator default) A JSON save answer carries the validity flag of the revision it describes, from the same evaluation as its derived values and checks; the module adds, rewrites or removes `#validity` only from an answer at least as new as the derived values and checks shown, so the flag never contradicts them.
- **ASSIST-22** (2026-10-20) The module asks for JSON with exactly one `Accept: application/json` header on the Name, General notes, field and cell routes; the answer describes the live revision (200 for saved and "No change", 409 and 422 for refusals) and every integer, count and revision in it is a string. Any other request gets the PRG page; new row, quick-add, row actions, switch and Undo stay PRG.
- **ASSIST-23** (2026-10-20, coordinator default) After a refused save with JavaScript (409, 422) the draft stays in its control without the unit's note, switch or Undo, the alert shows the saved value when the unit still has one, and that unit's `base` moves to L. After a conflict a save queued before it was shown is dropped, and leaving the field no longer sends the draft: only Enter or Save does, so a conflict is overwritten consciously. After a refused value a queued later entry is sent, and a corrected entry saves on leaving as usual.
- **ASSIST-24** (2026-10-20, coordinator default) The switch and Undo of a unit saved with JavaScript post through hidden forms of their own carrying the answer's revision; a page post (switch, Undo, row action, quick-add, new row) waits until every save in flight or queued has its answer, then goes only if its button still stands for the same action on the same note (a button the answer rebuilt for another note sends nothing, and the status line says why).
- **ASSIST-25** (2026-10-20, coordinator default) A "No change" answer leaves the controls as typed (they equal the saved value); only a saved answer replaces the control text, and only when the player has not typed since the request.
- **ASSIST-26** (2026-10-20) A cell whose answer names no route at the live revision (its row was removed, before or after the write) can no longer change or be posted: a text or number entry stays read-only to copy, a select stays disabled showing its choice, its Save is disabled, the alert (which describes the control) says why, and the module never posts it again, so a newer `base` is never paired with an old row index.
- **ASSIST-27** (2026-10-21, user) The interpretation model runs on the GPU when one is usable and falls back to the CPU (as HW-1): Vulkan on Linux and Windows, Metal on macOS, so no platform is designed out; the CPU path stays the guaranteed baseline. The start-up priming request measures the speed, and the job budgets are set from that measurement within fixed caps. This replaces the plan's earlier "no GPU" POC cut.
- **ASSIST-28** (2026-10-21, user) The model is an owner setting on the admin page: one validated free-text field, `hf:<org>/<repo>/<file>.gguf@<revision>` (Hugging Face only, exact revision) or `local:<file>.gguf` (a file already in the models folder; models from any other site are placed there by hand). The app downloads `hf:` models in the background (progress, cancel, resume, hash recorded and checked before each load), keeps the current model active meanwhile, shows the licence for the owner to confirm, and switches only after a trial (load, priming, a few synthetic phrases schema-valid) shows the measured speed; switching back is one click. Defaults by device: ASSIST-55. Downloads are owner-started, go only to Hugging Face and never carry sheet or player text.
- **ASSIST-29** (2026-10-21, user) Production never requires containers: the model server runs as a native process managed by Mimik on every platform; containers are for development and benchmarks, and the only container deployment is the whole app as one image (no container inside a container). The no-egress property in production comes from OS mechanisms, not Docker networks.
- **ASSIST-30** (2026-10-21, user; transport amended 2026-10-22) In production Mimik starts and stops an official llama.cpp `llama-server` build (Vulkan, Metal or CPU per platform) as a child process with a per-launch token. On Linux in the Hakoniwa sandbox (ASSIST-51) the child listens on a Unix socket in a private directory (it has no network namespace to reach otherwise); elsewhere, and in the Linux fallbacks, on `127.0.0.1` with a random port. OS hardening where available (ASSIST-34), and the assistant page states which protection is active. An in-process or pipe sidecar is not used.
- **ASSIST-31** (2026-10-21, user) CPU-path budget (ASSIST-L20): on a machine without a usable GPU the request sends only the fields related to the note, with the dynamic part at most 1 KiB, and the run deadline may reach 90 s; the GPU path keeps the 60 s cap and the 4 KiB bound. Both still come from the priming measurement within those caps (ASSIST-27).
- **ASSIST-32** (2026-10-22, user) Budget calibration: margin 1.25 over the slowest of the calibration samples, run-deadline floor 15 s (a limit on stuck requests, not a wait: GPU replies take about 1–4 s); on the CPU path queue wait plus run deadline is at most 120 s, and a job that cannot start in time is refused as busy. Jobs run one at a time (`--parallel 1`); parallel slots on the GPU path are a later measurement.
- **ASSIST-33** (2026-10-22, amended 2026-10-23, user) Mimik's release bundle ships the official llama.cpp release builds, pinned and hash-checked, with their licence and notices. The pin belongs to the bundle, not to the design: Mimik uses llama-server only through HTTP and command-line flags and must not depend on one exact version (ASSIST-46). llama.cpp is a separately executed build dependency, credited and pointed to (`SOURCE.txt` gives the upstream repository, commit and asset hashes; `BUILD.txt` the tag, build and commit), not shipped as source (ASSIST-47).
- **ASSIST-34** (2026-10-22, user) Model-server hardening on Linux, the Hakoniwa sandbox (ASSIST-51: private network, PID and mount namespaces, an allowlist of read-only paths plus the GPU device nodes, Landlock, seccomp, killed with Mimik); the active level is shown and logged. Unconfined (level 3) is not an automatic fallback (ASSIST-43). OpenFirma's `firma-run` crate is not a library dependency (closed launch API, unpublished, Authority/Sidecar stack). Windows is "not confined" for now; macOS and Windows runtime code is deferred, with no platform designed out.
- **ASSIST-35** (2026-10-22, user) Model downloads: at most 8 GiB; a model without a stated licence is allowed with a warning, and the owner's confirmation records the licence file's hash; the system proxy is used for downloads only, never for the model server; the OS certificate store; an enumerated list of exact Hugging Face hosts, checked on every redirect; gated repositories later.
- **ASSIST-36** (2026-10-22, user) A model trial stops the current model while it runs (players see "starting"); switching back stays one click.
- **ASSIST-37** (2026-10-22, user) Related fields sent as context: only the fields read together with the target, directly or through derived values; cells of other list rows are not sent.
- **ASSIST-38** (2026-10-22, user) Fraction words keep the 2b rule (any fraction word admits 2, 3, 4 and 100) until languages are handled generally; the derived-constant check is not adopted, and the provenance loophole it targeted is a known limit.
- **ASSIST-39** (2026-10-22, user) Mimik uses the latest stable Rust (1.99.1 now) and rig-core 0.45.0; the upgrade is its own reviewed change and re-runs 2b's rig-core checks.
- **ASSIST-40** (2026-10-22, user) The dev host may run the pinned official llama-server natively for the runtime-manager tests; installing additional software still goes through containers.
- **ASSIST-41** (2026-10-22, user) On the CPU path the model server uses the physical cores minus one (at least 1) by default, configurable; the budgets come from the calibration at that setting. The weekday 2-core rule governs the dev host only.
- **ASSIST-42** (2026-10-22, user) The shipped llama.cpp pin is release b11609 (commit `fcac190`), whose official Linux x86_64 assets are gzip tarballs (`llama-b11609-bin-ubuntu-x64.tar.gz` SHA-256 `f95cbb27dd6e377f2ce30f5cfd7ec987af3259c025fc7c98fff62927a16ff528`, `llama-b11609-bin-ubuntu-vulkan-x64.tar.gz` SHA-256 `8aff188828de76492343e19905f72408c10f5b870a03592155b0e7dd19b76ed0`): b11610, measured in 2b and 2c-1 from its Docker image (`sha256:217d278e…`), has no GitHub release assets, and its only commit after b11609 (`091b6a7`) changes the SYCL build script and docs, so the CPU and Vulkan source is identical to the measured build.
- **ASSIST-43** (2026-10-23, user) Level 3 (unconfined) is never used in 2c-2a: Mimik runs llama-server at level 1 or not at all, and where level 1 cannot be used the assistant is unavailable with how to fix it. Level 3's code stays built and unit-tested but unreachable from the manager, and the launcher refuses to start it; it returns later as its own step, explicitly allowed by the owner, never automatic. The guarantee covers what Mimik itself starts (the manager, Restart, the routes and the start-time probe, which runs level 1 only); `mimik assistant-runner --probe` is the one path that still runs level 3's probe, and it starts Mimik's own probe child under seccomp, never llama-server; the private `mimik assistant-runner` entry points (`--spec-fd`, `--probe-inner`) are an internal protocol between Mimik and its runner, not a privilege boundary: a local user able to run them can run llama-server directly anyway.
- **ASSIST-44** (2026-10-23, user) Any confinement weaker than the platform's strongest sandbox is used only when the owner has explicitly allowed it, never as an automatic fallback: on Linux that is level 3 (unconfined), the later owner opt-in step (ASSIST-43). By default the sandbox runs or the assistant is unavailable with how to fix it. The same rule applies to the macOS and Windows runtimes when they are built. A stored page setting may come with 2d-1.
- **ASSIST-45** (2026-10-23, user) The GPU stays the default model device when a usable GPU is found (ASSIST-27). On the GPU path the model server can issue any ioctl on its one render node, so its exposure to the kernel's graphics driver is wider than on the CPU path; the level-1 sandbox is otherwise the same: no network, no other processes and no access to the user's files; it reads the runtime and the model, read-only system libraries, system driver data (Vulkan ICD manifests, libdrm, drirc), the card's sysfs attributes and the CPU topology. This is accepted by default and shown to the owner on `/admin/assistant` ("Sandboxed, with graphics-driver access", naming `--assistant-device cpu` as the switch to the CPU): an explicit exception to ASSIST-44's rule against weaker confinement by default. The Vulkan loader (`libvulkan.so.1`) and the GPU driver are system dependencies, never bundled; the headers compiled into the upstream `libggml-vulkan.so` are an SDK build input of that binary, not shipped source.
- **ASSIST-46** (2026-10-23, user) Exact pinning must not freeze out security fixes. Mimik uses llama-server only through HTTP and command-line flags (no C++ API), so it does not depend on one exact version. (1) Our own release bundle keeps a pinned, hash-verified build; a scheduled CI job tries each new llama.cpp release against the test suite (flags, output parsing, grammar conversion, the confinement suite), so fixes reach users with the next Mimik release. (2) A later "system llama-server" mode, for distribution packages, checks compatibility instead of version at start: the required flags present in `--help`, the device listing and output formats parsing, and `/health`, `/tokenize` and a grammar request working; then it calibrates as usual. Any failure makes the assistant unavailable with the missing feature named. The hash check is replaced there by the package manager's signatures. Both are later work (TODO.md); neither is designed further now.
- **ASSIST-47** (2026-10-23, user) The release no longer ships llama.cpp's source archive: llama.cpp is a build dependency that is executed separately, not linked into Mimik. The release keeps the pinned llama-server binaries (`llama/`), their hashes and licence notices (llama.cpp's MIT text and the component licences, in `THIRD-PARTY-NOTICES.md`) and the pointer to the exact upstream tag, commit and asset hashes. The hash-verified source tar stays a build-time input of `llama-fetch` only, as the source of the notice texts. A future distribution package would depend on the distribution's llama.cpp; that needs its own decision on pinning and verification (ASSIST-46) and is not designed now.
- **ASSIST-48** (2026-10-23, user) There is no confinement level 2: Landlock-only confinement without namespaces is not built, and there is no `--assistant-allow-landlock`. The model server runs inside the platform's namespace sandbox or not at all, with no weaker automatic fallback. On Linux that sandbox is Hakoniwa (in-process Rust, ASSIST-51).
- **ASSIST-49** (2026-10-24, user) Inside the Hakoniwa sandbox Mimik adds a Landlock layer as defence in depth (not a confinement level, ASSIST-48): best effort.
