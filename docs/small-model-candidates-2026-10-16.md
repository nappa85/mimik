# Small-model candidates for the tool-loop benchmark (2026-10-16)

Status: research sheet produced by a read-only subagent on 2026-10-16. Nothing was downloaded or loaded. VRAM figures are estimates. The licence summaries are not legal advice; check the linked texts before redistributing anything.

This is a research sheet to support download approval. No weights were downloaded. The data comes from the HF API (`/api/models/<repo>/tree/main` and `?expand[]=gguf`), the model cards, llama.cpp source at the pinned commit `091b6a7fc` (b11610), and a read-only inspection of the pinned image. Vendor benchmark numbers are self-reported unless marked otherwise, and vendors report different numbers for the same model (see the notes).

## How the checks were run

- Image library location: `docker run --rm --network none --entrypoint sh <pinned image> -c 'ls -la /app'`. The architecture table is in `/app/libllama.so.0.6.0`. `strings` is not in the image, so the check used grep. Command:
  `docker run --rm --network none --entrypoint sh ghcr.io/ggml-org/llama.cpp@sha256:217d278e…ddfff -c 'grep -a -o -E "\b(minicpm[a-z0-9_]*|lfm[a-z0-9_]*|granite[a-z0-9_]*|llama[0-9]?|gemma[a-z0-9_]*|mistral[a-z0-9_]*|phi[a-z0-9_]*|…)\b" /app/libllama.so.0.6.0 | sort | uniq -c'`
  It found `llama`, `lfm2`, `lfm2moe`, `granite` (plus `granitemoe`, `granitehybrid`, `graniteswitch` and `granite_swa`), `mistral3`, `gemma4` and `minicpm5`. The `minicpm5` string belongs to the chat parser and is not an architecture.
- Cross-check: `src/llama-arch.cpp` at `091b6a7fc` maps `LLM_ARCH_LLAMA "llama"`, `LFM2 "lfm2"`, `LFM2MOE "lfm2moe"`, `GRANITE "granite"`, `MISTRAL3 "mistral3"` and `GEMMA4 "gemma4"`.
- Tool-call handling: I ran `common_chat_template_detect_params_init()` in `common/chat.cpp` at `091b6a7fc` against each GGUF's embedded `chat_template`, taken from the HF API. The script used the same substring rules. Template coverage comes from `tests/test-chat.cpp` at the same commit.
- KV estimate: f16 K and V at 24,576 tokens. The formula is 2 × attention-layers × kv_heads × head_dim × 2 B × ctx, with the inputs taken from each config.json. On top of that, assume about 0.4–0.7 GiB for compute buffers and output (not measured). The current runner uses `-ngl 99 --fit off` and the default f16 KV, with no `--cache-type-k/v`.

## Per-model notes

**MiniCPM5-2B.** It has the best claimed small-model tool scores, but every one of them is self-reported. The MiniCPM card scores LFM2.5-2.6B at BFCL v4 61.1, while LiquidAI's own card gives it 56.88, so cross-vendor tables do not agree. Daggers (†) mark several cells in the card table, and I could not find what they mean (**UNVERIFIED**). It is also **UNVERIFIED** whether the scores were run in thinking mode. The card recommends SGLang for tool calling; the pinned llama.cpp nonetheless has a dedicated MiniCPM5 parser. The template adds `<think>\n\n</think>` when `enable_thinking=false`, which is what the harness sends with `--thinking off`. Italian is not claimed, and with about 30% Italian cases this is the main risk. The license is Apache-2.0 with no extra terms.

**LFM2.5-2.6B and LFM2.5-8B-A1B.** Both cards describe these as reasoning models. The 2.6B card says it is "a pure reasoning model that always thinks". Neither template reads `enable_thinking`, so `--thinking off` has no effect. Expect `<think>` output and longer turns; the parser splits reasoning from content. The models are hybrid conv/attention, so the KV cache is very small, and the 8B-A1B activates about 1B parameters per token, so it should be fast. The 8B-A1B card contradicts itself (BFCLv4 48.50 vs 49.73).

The license is the [LFM Open License v1.0](https://huggingface.co/LiquidAI/LFM2.5-2.6B/blob/main/LICENSE). It reads like Apache-2.0: a perpetual, royalty-free copyright and patent grant. Redistribution must include the license, mark modified files, and keep the NOTICE and attribution notices. The difference is §5: *commercial* use is licensed only while you or your legal entity have annual revenue below US$10,000,000. Qualified non-profits doing non-commercial or research work are exempt from that threshold. The license has no acceptable-use policy clause. It permits our hobby and local use, and an open-source release of Mimik code is fine. Redistributing the weights or derivatives would have to carry the LFM license. This is not an OSI license.

**Granite 4.2 3B and 8B.** Italian is a "tested language". The license is Apache-2.0. IBM's own parser recommendation (`qwen3_coder`) matches the handler that b11610 auto-selects. The template defaults `enable_thinking` to True, so the harness's `enable_thinking=false` matters. The card says to use temperature 1.0 and top_p 0.95 for all tasks; the harness uses 0.1, which is a fidelity caveat for comparing with the card. On BFCL v4 the vendor scores the 3B and 8B equally (52.41 vs 52.39), and the 8B is only ahead on τ³ (58.06 vs 45.78). The 8B also needs `--cache-type-k q8_0 --cache-type-v q8_0` (quantised V needs flash attention on Vulkan) or partial offload at 24k, and the runner does not currently expose either. The fit with q8_0 KV is an estimate and has not been verified.

**Llama 3.1 8B Instruct.** This is the oldest candidate (2024). Its 76.1 BFCL is from an early BFCL version, and the independent BFCL v3 result is much lower (54.2 overall, 7.4 multi-turn). There is no official GGUF, and the base repo is gated (manual approval). The GGUF is bartowski's third-party conversion. At b11610, tool calls go through the generic autoparser, and the pinned tests do not check tool-call parsing for this template, so it is a real parse risk.

The license is the [Llama 3.1 Community License](https://github.com/meta-llama/llama-models/blob/main/models/llama3_1/LICENSE). If you redistribute, you must show "Built with Llama" prominently. Any derived *model* name must begin with "Llama". Redistributions must keep the notice "Llama 3.1 is licensed under the Llama 3.1 Community License, Copyright © Meta Platforms, Inc. All Rights Reserved." Use must follow the [acceptable use policy](https://llama.meta.com/llama3_1/use-policy). A separate license from Meta is required above 700M monthly active users. It is usable for our project, but it is not an open-source license.

**S1 Ministral 3 8B (suggestion).** It has the strongest independent Italian (ITALIC) and BFCL v3 numbers among the 8B dense options. These come from a single third-party paper evaluating BF16, not Q4_K_M. The GGUF is official and the license is Apache-2.0. It is a vision-language model: the runner passes `--no-mmproj`, and the text GGUF is enough. The fit needs q8_0 KV, the same as Granite 8B. A smaller sibling, `mistralai/Ministral-3-3B-Instruct-2512-GGUF`, would fit at f16: `Ministral-3-3B-Instruct-2512-Q4_K_M.gguf`, 2,147,023,008 B, `9ed150d4367e68df0ac8e1540f6ddc65b42d0ee26378329d1ecbca60f93fc5f8`, arch `mistral3`. It has no published tool score (**UNVERIFIED**).

**S2 Gemma 4 E4B (suggestion).** Its published agentic score is modest (Tau2 avg 42.2), and LiquidAI's and OpenBMB's comparison tables rank it below their own models. I list it because it has an official ggml-org GGUF, an Apache-2.0 license, a dedicated parser and a small KV cache. The official files are Q4_0 only. My KV estimate assumes llama.cpp honours KV sharing and the sliding window, which I have not verified.

**Not suggested.** I found no Phi model with recent tool-calling evidence: Phi-4-mini-instruct is from early 2025, and I did not find a newer sub-10B Phi.

## Recommended screening order

1. **Granite 4.2 3B**: Italian tested, Apache-2.0, official GGUF, fits at f16, and IBM's recommended parser is what the pinned build picks.
2. **LFM2.5-8B-A1B**: fits easily, fast MoE, Italian listed, strong vendor Tau² numbers. Caveats: it always thinks, and it uses the LFM license.
3. **MiniCPM5-2B**: tiny, with the highest vendor scores and a dedicated parser. Italian is the open question.
4. **LFM2.5-2.6B**: cheap to add next to item 2 (same parser and license).
5. **Ministral 3 8B** (suggestion): best independent Italian and BFCL evidence, but it needs a q8_0-KV option in the runner first.
6. **Granite 4.2 8B**: only worth it if the 3B shows promise. It needs q8_0 KV, and the vendor BFCL is no better than the 3B.
7. **Gemma 4 E4B** (suggestion), then **Llama 3.1 8B** last: weakest recent evidence for Gemma, and an untested parse path plus a restrictive license for Llama.
