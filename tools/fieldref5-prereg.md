# Field-reference experiment 5: the ASSIST-53 sentence in the prompt (decision rule, written before any run)

Prototype tier (AGENTS.md). Follow-up to experiment 3 (`docs/results.md`, "Field references,
experiment 3") and to the offline re-score under ASSIST-53, which re-scored stored replies that
were produced under the digits-only instructions. Nothing has been run for this experiment when
this is written.

## Question

1. Does the ASSIST-53 literal sentence in the prompt change the re-scored numbers? Experiment 3's
   replies were generated by a model that never saw the relaxed rule; here it sees it.
2. Does the Qwen3.5-9B (the ASSIST-55 GPU default) pass the screen bar with A (the shipped
   prompt) or with D53?

## Setup, identical for every run

- **Cases:** the same 30 cases `fr-01` to `fr-30` of `tools/assist-eval/fieldref-cases.json`,
  same Rust-rendered requests, expected values and `ref_fields`.
- **Settings as experiment 3:** greedy, `max_tokens` 352, primed, thinking off (`--reasoning off`),
  context 8192, pass 1 only, one run per arm and model, 6 threads on cores 0-5.
- **Models, in this order:**
  1. Qwen3.5-9B Q4_K_M (`qwen35-9b`), all layers on the GPU (`n_gpu_layers` 99), read from
     `/media/data/mimik/models`; arms A, then D53.
  2. Qwen3.6-35B-A3B Q4_K_M (`qwen36-35b-a3b`), `--n-cpu-moe 32`, container memory limit 22 GB,
     from a temporary copy on the SSD (below); arms A, then D53.
  Both files are the registry's pinned, hash-checked ones; the runner re-checks the SHA-256 of
  the file it is given before every model and refuses on a mismatch.
- **Hardware guards (the runner's):** RX 6650 XT, the GPU fan must be on manual with
  `pwm1 >= 230` (the runner refuses otherwise; set it before launching); thermal guard at
  junction 85 C, `MIN_AVAIL_GB` and the swap guard (swap growth above 512 MB after the load
  stops the run).
- **Machine:** the runs start after 18:00 on a weekday (no owner-window override), and no request
  starts at or after the next weekday 09:00. The runner refuses a busy host (`LOAD_MAX`).

## Arms

- **A** (`v2-compact`): the shipped prompt, as in experiment 3. Re-run, not reused: its prompt now
  carries the ASSIST-53 sentence.
- **D53** (`v2-ids-53`): experiment 3's arm D (context items named by id, no context values, the
  two reference examples, the id-keyed reply schema) built on the **current shipped instruction
  text**. It differs from `v2-ids` only in one sentence: the digits-only literal rule is replaced
  by the ASSIST-53 sentence (number words in English and Italian, and a redundant `* 1` or
  `/ 1` allowed). It is validated under the ASSIST-53 rule by default. Prefix SHA-256
  `ac46010cef3b18cfeee2a0e517c54571098174cdf783c5c7e7c01b3e18e9453f`
  (`v2-ids`: `1326c1983146284acfb8930eb0897c9f4d67c852bb27862af0c2332b884bf3e1`; unit tests pin
  both). A's prefix is the shipped one, `3cf169f2...ad057e`, unchanged.
- D53 is still a Python transform of the Rust-rendered request, not the Rust builder's output; a
  product change would need Rust support and a schema change (see experiment 2's limits).

## Metrics (as before, denominator 30 per arm)

correct_ref, false_confident, abstained (they sum to 30), dropped but right, output tokens p50,
total latency p50, schema validity, truncation, coincidences, peak junction, swap growth. A and
D53 are both scored under the ASSIST-53 rule (A's contract already does), so their numbers are
comparable with experiment 3's re-scored column. A run is void unless all 30 cases completed in
every arm (the runner exits 1 and the run is repeated).

## Decision rule

- **Screen bar:** correct_ref at least 24 and false_confident at most 3. Passing means only "not
  rejected on this screen".
- **Question 1:** for each model and arm, compare the live numbers with the re-score (9B: A 20/7,
  D 25/4; 35B: A 23/5, D 24/2, as correct_ref/false_confident). A difference of 3 cases or more
  in correct_ref or false_confident is material; smaller ones are noise. D53 against the
  re-scored D is the direct test of the sentence; A against the re-scored A shows the
  run-to-run and server drift (greedy, so a difference there is not sampling noise, and the
  prompt text of A did not change).
- **Question 2:** the 9B passes with an arm if that arm meets the bar. If both pass, prefer A
  (it is the shipped prompt, no Rust change). If only D53 passes, the finding is that the 9B
  needs the ids prompt, which needs Rust support before it can ship. If neither passes, the 9B
  does not meet the bar on this screen and the 35B result is the reference.
- A pass is a candidate only; it needs held-out cases and an independent adversarial review
  before any default-model or product decision.

## Limits, stated in advance

- The 30 cases are dev cases already seen; this is not a held-out result.
- One run per arm and model, one sampler, 30 synthetic cases. With n = 30, a difference under 3
  cases is noise.
- The 35B runs with experts in RAM; its latency depends on the host and is not a product figure.
- Both arms carry the ASSIST-53 sentence now; experiment 3's A and D carried the digits-only one.
  A's live numbers against its re-score therefore measure the sentence on A, and D53's against
  the re-scored D measure it on D. Neither arm isolates other drift (server image and model
  files are the same pins as experiment 3).
- The 9B's memory limit (14 GB, the registry's) and `MIN_AVAIL_GB` 8 are set here, not carried
  over from a previous run.
